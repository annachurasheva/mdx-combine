## Правило одного файла

В `src/` лежит только `mdx-combine.html`. Эксперименты — в `archive/`.
Файл никогда не сохраняется из браузера (Ctrl+S убивает разметку и порождает `*_html.txt`).

## Команды (Ctrl+Shift+P → Run Task)

| Команда | Зачем | Нужен Node |
|---|---|---|
| Edge: открыть рабочий комбайн | открыть src/ в браузере | нет |
| Edge: doctor | проверить файл перетаскиванием | нет |
| Проверка: линтер комбайна | Ctrl+B: дефекты в Problems | да |
| Доставка: .md в Astro-проект | inbox/ → posts/, с валидацией | да |
| Архив: снять копию версии | копия в archive/ + запись в VERSIONS.json | да |

## Рабочий цикл

1. Открываешь комбайн в Edge, смотришь номер build в шапке.
2. Собираешь пост → Edge кладёт .md в inbox/.
3. «Доставка» → файл проверяется и переезжает в проект.
4. В Astro-проекте: Ctrl+B (проверка frontmatter) → сборка.

## Отметка версии

В комбайна обязателен комментарий `<!-- build: X.Y.Z -->`,
а в шапке интерфейса — вывод `<span id="buildStamp">`. Иначе непонятно, что открыто.

## Для разработчиков

### Структура репозитория

```
mdx-combine/
├─ src/mdx-combine.html      ← ЕДИНСТВЕННЫЙ рабочий файл
├─ inbox/                    ← Edge складывает готовые .md
├─ archive/                  ← пробники(тесты)  старых версий
├─ scripts/
│   ├─ check.mjs            ← линтер комбайна (Ctrl+B)
│   ├─ promote.mjs          ← доставка inbox/ → posts/
│   └─ archive.mjs          ← копирование версии в archive/
├─ doctor.html              ← проверка комбайна без Node
├─ VERSIONS.json            ← манифест версий
├─ CHANGELOG.md             ← история изменений
├─ README.md	            ← этот файл 
└─ mdx-combine-README.md    ← ТЗ для комбайна
```
