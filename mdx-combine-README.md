## 0. Правила работы для ИИ-ассистента

Прочитай до того, как отвечать.

1. **Отдавай файл целиком, а не патч текстом.** Описание «замените строку 23» не принимается: я копирую фрагменты с ошибками. Нужен готовый `mdx-combine.html` целиком или файл-ссылка.
2. **Никаких `\$`.** При переносе кода из чата у меня стабильно появляются артефакты экранирования: `\${data.title}` вместо `${data.title}`, `/^[a-z0-9\-]+\$/` вместо `/^[a-z0-9-]+$/`. Если даёшь JS с шаблонными строками или регулярками — перечитай их и убери обратные слеши. Это главная причина нерабочих версий.
3. **Никакого терминала как условия работоспособности.** Комбайн = один HTML-файл, который открывается двойным кликом в Edge по `file://`. Node, pnpm, npm install, npx, сервер, базы данных — вне этого файла. Скрипты обвязки (`.mjs`) — только помощники, комбайн без них обязан работать.
4. **Новые зависимости запрещены.** Ни CDN, ни `<script src>`, ни import. Всё внутри одного файла.
5. **Не переименовывай `id` элементов и не меняй их на ходу.** `getElementById` и разметка должны сходиться. Если меняешь — проверь все обращения.
6. **Не изобретай библиотеки и API.** Если чего-то не знаешь — скажи прямо, не выдумывай названия функций и опций темы.
7. **Не трогай то, что уже работает, без запроса.** Список решённого — раздел 11.
8. **Не добавляй полей в frontmatter «на всякий случай».** Состав полей строго из раздела 4.
9. **После выдачи кода — чек-лист из раздела 10**, а не «попробуйте и скажите».

## 1. Что это за проект

**MDX-комбайн** — локальная HTML-страница для Edge, которая делает из скопированного куска страницы готовый пост для блога на Astro (тема Retypeset).

Цепочка:

```
страница в интернете (Web Archive / Gmail / свой сайт)
        ↓  Ctrl+C
Edge: mdx-combine.html   ← я заполняю поля формы
        ↓  Generate → Download
inbox/*.md               ← папка загрузок Edge
        ↓  promote.mjs (валидация)
src/content/posts/*.md   ← Astro-проект
        ↓  Ctrl+B (проверка frontmatter) → сборка
```

Задача комбайна — **исключить ручное заполнение frontmatter «на глаз»**: обязательные ячейки не должны оставаться пустыми, а файл с браком не должен доезжать до проекта.

### Окружение (реальное, не вымышленное)

| Параметр | Значение |
| --- | --- |
| ОС | Windows |
| Браузер | Microsoft Edge, единственный |
| Способ запуска | двойной клик по файлу, протокол `file://` |
| Node на входе | отсутствует, не требуется |
| Язык интерфейса | русский |
| Проект блога | Astro + тема Retypeset, контент в `src/content/posts/` |

### Про исходную тему (чтобы не путать источники правил)

- Комбайн пишу я, под себя. Автор темы Retypeset — `radishzz`.
- В теме есть скрипт `format-posts.ts`: он разделяет frontmatter и тело регуляркой `/^---\r?\n([\s\S]+?)\r?\n---\r?\n([\s\S]*)$/m`. Эту же регулярку используй в проверяющих скриптах — **одну на всё**, вторую не изобретай.
- `autocorrect-node` в том скрипте чинит пробелы только между CJK-символами (китайский/японский/корейский). **Для русского текста бесполезна, не предлагать.**
- `description` в frontmatter генерируется самой темой на основе `toc` и отдельной настройки объёма (вне комбайна). В моём файле поля `description` **не было, нет и не будет**.

## 3. Правила frontmatter — жёсткие

Порядок ключей фиксирован. Состав ключей фиксирован.

| Ключ | Обязат. | Формат | Правило | Почему |
| --- | --- | --- | --- | --- |
| `title` | да | строка | без кавычек; не пустая | заголовок поста |
| `abbrlink` | **опционально** | `/^[a-z0-9-]+$/` | строчные, цифры, дефис. **Без `_`, без заглавных** | ключ URL; если поле пустое — ключ не выводится в frontmatter вообще; **не участвует в имени файла** |
| `published` | да | `YYYY-MM-DD` | **ручной ввод**: дата оригинального поста на архивном источнике; поле `input type="date"`; валидация `^\d{4}-\d{2}-\d{2}$`; по умолчанию пусто; в `localStorage` НЕ сохраняется | ISO с `T`/`Z` роняет сборку |
| `updated` | да | `YYYY-MM-DD` | **автоматически**: дата генерации, `new Date().toISOString().split('T')[0]`, без кавычек, без `T`/`Z` | дата перепоста |
| `tags` | да | YAML-список | каждая строка `  - Tag` (дефис + пробел) | em-dash вместо дефиса ломает YAML |
| `draft` | да | `false` / `true` | без кавычек | булево |
| `pin` | да | `0` / `1` | без кавычек | булево-число |
| `toc` | да | `false` / `true` | булево | управляет генерацией авто-описания темой Retypeset; объём (128/256) настраивается отдельно, вне комбайна |
| `lang` | да | `'ru'` и т. п. | в кавычках | язык поста |
| `authorIds` | да | YAML-список `  - nevzorov-b-i` | **не строка** | тема ждёт список ссылок |
| `description` | **нельзя** | — | не выводить никогда | конфликтует с `toc`, роняет сборку |

Ровно так выглядит правильный вывод:

```yaml
---
title: Братская могила в Корпечи
abbrlink: bratskaya-mogila-v-korpeche
published: 2016-10-26
updated: 2026-09-29
tags:
  - history
  - crimea
draft: false
pin: 0
toc: true
lang: 'ru'
authorIds:
  - nevzorov-b-i
---
```
 published — дата источника, вручную; updated — дата генерации, автоматически

## 4. Требования к интерфейсу («защита от дурака»)

Я делаю ошибки при заполнении — интерфейс не должен их пропускать.

1. **Пустая обязательная ячейка не существует как состояние.** Пока `title`, `abbrlink` (валидный) и `content` не заполнены — кнопка Generate неактивна, а не выдаёт ошибку по клику.
2. Красная рамка + текст ошибки **под конкретным полем**. `title` и `abbrlink` — в разных карточках, иначе сообщение об ошибке одно на двоих и врёт.
3. `abbrlink` — только ручной ввод. Поле пустое, пока пользователь сам не введёт значение. Никакого автозаполнения из title, никакой синхронизации. `localStorage` (с префиксом `mdxc:`) помнит последний введённый abbrlink для автоподстановки, но НЕ title, НЕ slug, НЕ контент.
4. Транслит полный: все 33 буквы, `ё`→`yo`, `щ`→`sch`, `ъ`/`ь` → пусто. Символ `_` из slug вырезать (`[^a-z0-9-]`), иначе валидатор вечно ругается.
5. **Память последнего заполнения** через `localStorage` с префиксом `mdxc:` — для авторов, тегов, pin, draft, toc, lang, **и abbrlink**. `title`, `slug`, контент **не сохранять**: иначе следующий пост серии унаследует чужой slug. Нужна кнопка «Сбросить память».
6. Любая правка поля после Generate **гасит** Download/Copy — нельзя скачать устаревший файл.
7. Preview показывает ровно то, что уйдёт в файл. Никаких расхождений.
8. **Имя файла** — всегда только `<slug>.md`, где `<slug>` = транслит заголовка (readonly-превью). `abbrlink` **не участвует в имени файла вообще**. Если abbrlink заполнен и валиден — он попадает во frontmatter отдельным ключом, но имя файла остаётся `<slug>.md`.
9. `published` — поле даты с ручным вводом и валидацией; пока дата невалидна или пуста, Generate неактивна; ошибка — под полем. В `localStorage` не сохраняется (у каждого поста своя дата источника). `updated` в интерфейсе не показывается — подставляется при генерации.
10. Метка версии в `<head>` (`<!-- build: X.Y.Z -->`) и рядом с `<h1>` — иначе непонятно, какая из семи копий открыта.

## 5. Контент и картинки

- Вход: HTML **или** уже готовый Markdown (Web Archive и Gmail выдают готовый Markdown с конструкциями `[![alt](url)](url)`).
- **Готовый Markdown не пережёвывать.** Конвертер HTML→Markdown включать только если в тексте реально есть HTML-теги.
- Картинки тянутся с внешних адресов — локализация не нужна, достаточно, чтобы `![alt](https://...)` доехал до Astro целым.
- Ссылки вида `.../web/20161026035710im_/http://...jpg` НЕ трогать: `im_/` — рабочий префикс веб-архива для картинок; его удаление ломает изображение. Абсолютные URL проходят как есть; в `/assets/` уходят только относительные пути.
- Картинки не терять: при конвертации `img` → `![alt](src)`, `src` берётся как есть, относительные пути → `/assets/`.
- `pre/code`, списки, ссылки, `strong`/`em` — конвертировать; лишние `<div>` из копипасты убирать.

## 6. Проверенные грабли (узнать по симптому)

| Симптом | Настоящая причина | Лечение |
| --- | --- | --- |
| В файле написано `${data.title}` текстом | артефакт экранирования `\$` из чата | убрать обратные слеши |
| Кнопка Generate вечно серая | регулярка `/^[a-z0-9\-]+\$/` — `\$` требует символ `$` в конце | `/^[a-z0-9-]+$/` |
| дата с запятой или временем | `.split('T')` возвращает массив; ручной ввод без валидации | `updated` — `.split('T')[0]`; `published` — ручной ввод через `input type="date"` + регулярка `^\d{4}-\d{2}-\d{2}$` |
| Сборка Astro падает на дате | ISO с `T` и `Z` | только `YYYY-MM-DD` |
| Файл «иногда не скачивается» | `revokeObjectURL` сразу после `click()` и `a` не в DOM | `body.appendChild(a)` → `click()` → `setTimeout(revoke, 1000)` |
| «Копировать» молчит | `navigator.clipboard` недоступен на `file://` (не secure context) | fallback: выделить `<pre>`, `document.execCommand('copy')` |
| `authorIds` сломал шаблон вывода | строка вместо YAML-списка | `authorIds:` + перенос + `  - id` |
| `toc` не true/false | в `<select>` три option или значение 128/256 | ровно два option: `true` и `false`; числа не допускаются |
| Slug `test_1`, поле вечно красное | `\w` в `slugify` пропускает `_` | `[a-z0-9-]`, символ `_` удалять |
| Картинки из Web Archive битые на сайте | из img-URL вырезан `im_/` | URL не трогать; `im_/` сохранять;
| «Файл не тот» | сохранение страницы из браузера → `*_html.txt`, разметка убита | файл правится только в VS Code; Ctrl+S в Edge запрещён |
| Память не работает | разные профили Edge → разный `localStorage` | один рабочий профиль |
| `getElementById` вернул null | `id` переименован при правке | проверь все обращения (есть в `doctor.html`) |
| Скрипт вообще не исполняется | незакрытый шаблонный литерал (нечётное число \` ) | проверка чётности \` в линтере |
| Ссылка работает, картинка битая | href и src в разных формах порчи | целевая форма одна: `web/<14 цифр>im_/http://…`; формы порчи: `im_http://` (нет слэша), `<цифры>http://` (нет im_/ и слэша), `<цифры>/http://` (нет im_/) — все чинятся вставкой `im_/` после 14 цифр |
| Текст «стеной»: стыки «оккупантов.В», «Родины.Боевые» на сайте и в RSS | развёртка div в конвертере шла через `textContent` — внутренние `<p>`/`<br>` умирали, абзацы склеивались; источники держат абзацы в div/br без `<p>` | (1) конвертер: div развёртывать только через `innerHTML` с пустыми строками — `el.outerHTML = '\n\n' + el.innerHTML.trim() + '\n\n'`, порядок шагов br → hr → div → p (исправлено в 1.1.4); (2) старые .md чинить `scripts/fix-glue.mjs` (Node; по умолчанию сухой прогон, запись с `--apply`); регулярка — только в `\u`-кодах: стык = 2+ строчных/цифр + точка + заглавная, после которой строчная или пробел; предохранители — инициалы «С.В.» (заглавная перед точкой), одиночные «г./с.» (не проходит `{2,}`), многословные сокращения `гор.`, `дер.`, `сел.`, `пос.`, `ул.`, `пер.`, `ст.`, `тов.`, `им.`, `гос.`, `кап.`, `лейт.`, `ген.`, `ком.`, `ред.`, `изд.`, `стр.`, `гл.` через `\b`-lookbehind; (3) в поиск VS Code эту регулярку НЕ вставлять: движок не поддерживает lookbehind переменной длины («length of lookbehind assertion is not limited»), а кириллические диапазоны при копипасте подменяются латиницей и превращаются в мега-диапазон, бьющий по URL — исполнение только в Node |

## 7. Как проверять результат

**Без Node:** открыть `doctor.html` в Edge, перетащить туда `mdx-combine.html` → список ERROR/WARN (артефакты `\$`, дата, `toc`, `authorIds`, битые `id`, нечётные \` , дубли `id`).

**С Node:** `Ctrl+B` в VS Code → `scripts/check.mjs`, ошибки вспыхивают в Problems со ссылкой на строку.

### Ручной чек-лист перед скачиванием

- [ ] `published:` = дата оригинала на источнике (вручную), формат `YYYY-MM-DD`
- [ ] `updated:` = сегодняшняя дата (автоматически), формат `YYYY-MM-DD`, не `''`
- [ ] `description` в превью отсутствует
- [ ] `tags:` и `authorIds:` — списки с `  - `, не em-dash и не строка
- [ ] `abbrlink` без заглавных, без `_`
- [ ] файл реально скачался и открылся не нулевым размером
- [ ] метка `build` в шапке совпадает с комментарием в `<head>`

### Проверка в Astro-проекте

`promote.mjs` переносит файл из `inbox/` в `src/content/posts/` **только если ошибок нет**. Файл с пустым полем или кривой датой остаётся в `inbox/` физически — это не подсказка, а блок.

## 12. Готовая формулировка запроса к ИИ-ассистенту

Копируй вместе с файлами.

> Прилагаю: `mdx-combine-README.md` (ТЗ и правила), `mdx-combine.html` (рабочий файл).
> Задача: **[что изменить]**.
> Условия: файл один, открывается двойным кликом в Edge по `file://`, без Node и без внешних библиотек. Отдай **весь файл целиком**, готовый к сохранению как `mdx-combine.html`.
